Canonical application specimen

Quiet hierarchy for serious tools.

Stack Junkie application styling is not a coat of dark paint. It is a disciplined system for placing the current task first, keeping technical detail available without frontloading it, and proving that the real interface remains clear in every state and size.

A styled surface must
  • Use semantic foundations, not scattered literals.
  • Make the primary task obvious within five seconds.
  • Reflow without clipping, overlap, or microscopic type.
  • Show feedback, error recovery, and real workflow states.
  • Provide screenshot evidence and independent visual review.

Reflow order

  • 1Reduce nonessential whitespace within the spacing scale.
  • 2Wrap labels and prose at word boundaries.
  • 3Move rare actions into clearly labeled disclosure.
  • 4Collapse secondary panes, then stack independent regions.
  • 5Scroll the correct region in one direction.

Never shrink past usability

  • ×No whole-interface transform scaling.
  • ×No natural-language word splitting or required-label ellipsis.
  • ×No controls below pointer or touch target floors.
  • ×No microscopic text used to avoid responsive layout work.
  • ×No two-direction scrolling outside intrinsically spatial data.

Reference evidence

Approved examples anchor the visual character. The anti-example anchors what the system must prevent.

Stack Junkie website, dark

Canonical palette, editorial hierarchy, flat surfaces, restrained blue, and quiet metadata.

Stack Junkie website, light

Warm off-white foundation, white content layers, thin borders, and the same typographic roles.

EasySpeechToText, dark

A compact desktop translation that keeps one obvious recording action and minimal permanent chrome.

EasySpeechToText, light settings

Dense configuration with restrained layers, concise labels, clear grouping, and a persistent save action.

Anti-example: simultaneous competition

The large explanatory dialog, underlying workbench, side panels, transport controls, status text, and diagram all demand attention together. Several labels clip despite the large window. The repair is to keep the active task and state primary, move the report or tutorial to a dedicated surface, collapse secondary inspectors, and disclose help contextually. Smaller text alone would make this worse.

Verification gate

A build passing is not visual proof. A checklist passing without images is not visual proof. The implementation and approval roles remain separate.

Real product screenshots cover every changed surface, implemented theme, required state, and normal, narrow, and minimum size.
